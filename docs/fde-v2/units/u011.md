# AIFDE-V2-U011: Versioned small corpus and SQL metadata

**Learner status: Not started.** This is a dependency unit, not a calendar day. Scheduled segments: Day 14: primary 30 min, Day 15: primary 60 min, Day 15: buffer 30 min.

## Prerequisites

U003 document validation and U004 supplied metadata endpoint; Day14 starts only a partial row slice.

## Learn

SQLite transactions make a batch atomic. An idempotent ingest means repeating the same identifier, version and content hash leaves exactly one unchanged record. A changed record must advance exactly one version; reject stale, skipped or same-version changed text. Keep the five-column published `documents` metadata shape stable; source text is persisted separately.

Reference: [SQLite UPSERT](https://sqlite.org/lang_UPSERT.html) and [SQLite transactions](https://sqlite.org/lang_transaction.html).

## Learner-owned task

Complete the learner `ingest_versioned_document` seam for all ten synthetic records in the checked-in CC0 fixture. Record document ID, version, title, source and SHA-256, persist text separately, and implement insert / exact-repeat / next-version update rules. Run the supplied aggregate query that counts documents by version; record licensing/source.

**Learner seam:** `learner.ingest_versioned_document(raw, corpus)`

## Acceptance

Exact repeated input changes no row count or values. Same version with changed text, stale version and skipped version reject without changing metadata/body. Version+1 with changed text updates the existing ID exactly once and removes stale SQL chunks. The aggregate query returns ten documents and counts by version. No private data, PDF/OCR or unlicensed content.

**Command:** `python3 scripts/fde_v2_seed_corpus.py --limit 10` (after implementing this seam); `python3 -m unittest ai.fde_v2.learner_acceptance.test_continuation_units.ContinuationAcceptance.test_u011_versioned_ingestion`
