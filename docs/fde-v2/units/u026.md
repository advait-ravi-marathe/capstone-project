# AIFDE-V2-U026: Honest latency and resource baseline

**Learner status: Not started.** Scheduled Days34–36 (30 minutes primary on Day34, 60 minutes Day35, 30 minutes buffer Day36). The fixed workload is twelve loopback requests at concurrency one, with request one first/cold-or-first and eleven subsequent requests. It is intentionally small and is not a throughput claim.

## Learn and do

Read Python's official [`time.perf_counter()` documentation](https://docs.python.org/3/library/time.html#time.perf_counter), then inspect `scripts/fde_v2_local_benchmark.py`. It measures client end-to-end time and reports server retrieval/generation stage timings from each actual response. It records platform/CPU metadata, explicitly states that this API does not expose model-process RSS telemetry, and records local provider cost as unavailable.

Run only against the supplied loopback API. It refuses remote targets and refuses to overwrite an existing report:

```sh
python3 scripts/fde_v2_local_benchmark.py
```

The script makes twelve real `/ask` requests. If model/vector artifacts or learner seams are unavailable, it stops with a blocked/failed message; do not replace the endpoint with a fixture or invent latency numbers. A real request set can take several minutes because model calls are sequential and bounded.
