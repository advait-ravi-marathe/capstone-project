# AIFDE-V2-U024: Reproducible build and CI boundary

**Learner status: Not started.** Scheduled Days32–33 (90 minutes primary +30 minutes buffer). This is a local application-container smoke, not a cloud deployment or a model/RAG pass.

## Learn and do

Read the official [Docker build overview](https://docs.docker.com/build/concepts/overview/) and [GitHub Actions workflow syntax](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions). The container contains only the API runtime dependencies. Model and embedding weights are deliberately not copied into the image. The existing workflow installs the pinned project dependencies and runs deterministic acceptance; the added container smoke proves only that a fresh API image starts, reports health, and refuses `/ask` with 503 while real artifacts are absent.

Day32: inspect `Dockerfile.fde-v2-api`, `requirements-fde-v2-api.txt`, and the CI step. Read each command and identify the bind address, port, health route, and model-unavailable behavior. Run the bounded container smoke from the repository root:

```sh
python3 scripts/fde_v2_container_smoke.py
```

The script builds the image, binds the host port to `127.0.0.1`, checks the exact `/health` response, checks `/ask` fails closed without model files, and removes the temporary container/image. A successful container check is not evidence of RAG or production readiness.

Day33: use the 30-minute buffer only for a reproducibility defect or a clean-run retest; if no defect is observed, record that fact and the exact environment. After installing the documented pinned Python requirements and frontend lockfile, the aggregate deterministic check is:

```sh
scripts/fde_v2_clean_check.sh
```

## Acceptance and evidence

Record commit, Python/Docker versions, exact build/run result, health status, expected model-absent 503, and cleanup result. Fresh deterministic tests must need no credentials or model weights. Keep the real local RAG receipt separate. No hosted deployment, public bind, cloud account, or paid resource is authorized by this unit.
