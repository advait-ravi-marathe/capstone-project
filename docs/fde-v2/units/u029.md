## Learn and do

After confirming the prompt, model, corpus and configuration are frozen, run the real loopback held-out command once:

```sh
python3 scripts/fde_v2_run_p1_heldout.py
```

This uses the six answerable, two unanswerable and two adversarial source cases in `ai/fde_v2/coverstory/evals/questions-heldout.jsonl`. It records only actual API outcomes and returned citations/source text; it does not grade semantic correctness. If any model is unavailable, it writes a blocked/failed attempt and exits nonzero. That artifact cannot be converted into a pass by editing status fields.

Separately review each actual answer against the cited fictional source passage using `docs/fde-v2/templates/u029-grounding-review.json`. The review binds to the exact run digest and requires explicit correctness/support, fabrication and adversarial-boundary judgments. Do not use a model's own confidence or its citations as the correctness oracle. After completing that review, run:

```sh
python3 scripts/fde_v2_check_p1_audit.py .runtime/fde-v2/p1-heldout-run.json .runtime/fde-v2/p1-heldout-review.json
```

The CLI reports the submitted counts against the proposed target but explicitly cannot verify reviewer independence or award P1.

## Acceptance and evidence

The proposed release target is at least 5/6 answerable outputs judged correct and supported, 2/2 unanswerable outputs not fabricated, and no deterministic access-boundary failure; all citations resolve. The check script verifies evidence shape and digest binding, not the human semantic verdict. A few synthetic cases do not establish enterprise safety or quality. If the real-model gate is blocked, leave this evaluation unmet and record the exact reason.
