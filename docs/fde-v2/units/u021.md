# AIFDE-V2-U021: Failure taxonomy and traces

**Learner status: Not started.** This is a dependency unit, not a calendar day. Scheduled segments: Day 28: primary 60 min, Day 29: primary 30 min.

## Prerequisites

U019 RAG and U020 explicit abstention result.

## Learn

Useful evaluation records identify the case, outcome, failure stage and model/configuration version without copying questions, source text or generated answers into default logs. Record stage timing and a non-sensitive trace ID. A trace does not establish production observability.

Reference: [FastAPI Handling Errors](https://fastapi.tiangolo.com/tutorial/handling-errors/); use structured application logs only as supplied infrastructure.

## Learner-owned task

Day 28 is the first 60-minute segment: implement the per-case failure classifier and start redacted eval-record building. Day 29 supplies the final 30-minute segment to run the development evaluation across retrieval, unsupported generation, wrong citation, schema, latency/availability and input-validation examples, then select one repair from observed failures. Do not claim U021 complete before the Day 29 segment and acceptance run.

**Learner seam:** `learner.classify_failure(...)` and `learner.build_eval_record(...)`

## Acceptance

Every case has a record; stage/timing names and finite nonnegative timing values validate; failure categories map to the taxonomy; model revision and 64-hex config digest are present; question, answer and raw source text are absent. Evidence includes per-case results and one limitation.

**Command after the Day 29 segment:** `python3 -m unittest ai.fde_v2.learner_acceptance.test_continuation_units.ContinuationAcceptance.test_u021_failure_taxonomy_and_redaction`
