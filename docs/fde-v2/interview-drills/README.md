# Bounded 14-day role-bank practice inventory

This is the concrete practice layer for the `role-bank-rotation.json` cycle. It occupies exactly 30 minutes/day; it does not add work to the 60-minute separate DSA block or 90-minute AI block. Any code change is made in a disposable scratch copy, never in the capstone. Preserve the first attempt and log tool/help use. Assistant-authored plumbing and fixes are not learner implementation evidence.

The day1 exercise is pinned to Spring Boot3.5.6 and Maven3.9.9, uses real `@WebMvcTest`/`MockMvc` context, Jakarta validation and injected service boundary; `verify.sh` checks expected-red starter then a separately overlaid reference. The Maven distribution is checksum-verified; project dependency versions are pinned and fetched from Maven Central. Both caches stay beneath the drill's ignored `.mvn` directory. See the [official Spring Boot MVC testing reference](https://docs.spring.io/spring-boot/3.5/reference/testing/spring-boot-applications.html) and [Spring MVC validation reference](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-validation.html). The Java-only `SpringServiceBoundaryDrill.java` remains a framework-free concept fixture; the new separate project tests actual Spring behavior. Neither fixture tests authentication or establishes production security. The frontend fixtures are separate from the capstone application. For timed drills, preserve the starter in version control or copy it to a disposable scratch path, run the failing regression, make the bounded change there, and rerun the same regression. The reference versions are instructor controls, never learner results. The SQL lab uses in-memory synthetic rows and makes no performance claim. The concurrency fixture forces both duplicate requests past the idempotency lookup before either commits, so the seeded failure is deterministic rather than intermittent.

## 30-minute execution for coding slots

Use the same bounded timing for each Java or React exercise: 3 minutes to restate the prompt and constraints, 17 minutes to diagnose and make one scratch-only fix, 7 minutes to run the seeded regression and inspect the expected reference behavior, and 3 minutes to record feedback, tool/help use, and a spaced retry target. The harness proves the supplied starter is red and the instructor reference is green; the learner's own scratch copy must be run separately and its diff/output retained. An uncompleted fix is recorded as such, never replaced with the reference result.

## Checkable practice rubric

Score each attempt 0/1 on each item (0–4 total); this is a practice feedback tool, not an employer cutoff or readiness certification.

1. **Evidence:** cites the exact supplied file, test/trace/official section and command; separates observed from assumed facts.
2. **Diagnosis:** identifies the relevant control/data path and explains a causal failure or tradeoff, not just a code location.
3. **Action:** coding drill makes the smallest scratch-only change and demonstrates regression red→green; the seeded tests under `scripts.test_fde_v2_interview_drills` verify red starter and green separate reference. Non-coding drill makes a bounded recommendation that follows from the cited constraints.
4. **Limits:** states scope, risks and what remains unverified; records tool/help use and preserves the original attempt.

The learner records each score with the four item-level reasons, duration and a concrete retry target. A repeat uses a fresh case/variant when called “unseen.” A score does not establish role readiness, production experience, customer impact or independent capstone delivery. AWS activities are study/design only unless a separately authorized live lab exists.
