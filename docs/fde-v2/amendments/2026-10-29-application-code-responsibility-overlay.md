# Recommended-route overlay: application code is assistant-owned

Status: binding execution amendment for the selected 382-day dual AI/FDE + production-ML route. This overlay changes who performs application-plumbing work; it does not edit the hash-bound v2.4 contracts, their historical daily pages, or learner evidence. Use it together with the [production-ML depth amendment](2026-10-29-production-ml-depth-amendment.md).

## Responsibility rule

The assistant supplies and maintains the capstone's working frontend, backend, API, authentication, storage, deployment, test harness and operational plumbing. The learner does **not** write, edit, or implement those capstone application components, even from a starter or partially completed file. This includes React/UI, HTTP routes/controllers, API schemas/validation, auth middleware, SQL schema/migrations/queries, vector-store integration, Docker/IaC, and general service glue.

Learner-owned code remains appropriate for the specifically authorized AI/ML capability: model/loss/optimizer/training code, feature or sampling logic that is part of the model, evaluation/statistical functions, and ML-specific inference adapters. DSA remains a separate 60-minute block in the separate repository. The user has also approved short interview-focused FE/BE coding/debugging drills inside the existing 30-minute role bank, using existing code or isolated snippets; these are not capstone implementation tasks and must not expand the 180-minute day. Do not use generated application code as evidence of learner implementation or independent software delivery.

For application/backend concepts, use the supplied running code. The learner traces a real request and its data, reads logs/traces, inspects SQL with `EXPLAIN QUERY PLAN`, predicts consequences of a supplied diff/configuration change, diagnoses a seeded defect, compares concrete design alternatives against observed constraints, and explains an architecture choice. The assistant makes and applies any requested code repair. No generic architecture essay substitutes for this concrete work.

## Backend and frontend concept practice

Use one concrete, running application lesson at a time, within the existing day’s AI90 allocation:

1. **Trace (15 min):** start from a user action and identify request ID, route, validation/auth decision, storage/model call, response and rendered state using source plus logs/traces.
2. **Predict (10 min):** read a small supplied diff or configuration change and write the expected behavior/failure before running the check.
3. **Diagnose/review (55 min):** run the existing test or bounded local exercise; inspect SQL query plans/indexes or trace spans where relevant; find the root cause in assistant-supplied code; choose and justify the smallest safe remediation. The assistant applies it.
4. **Evidence (10 min):** record command, observed output, exact source/diff reference, learner’s reasoning, scaffold author and unresolved limitation.

Examples of concrete backend decisions: transaction boundary and idempotency; index selectivity and query-plan tradeoffs; tenant/ACL filtering; cache invalidation after revocation; queue/retry/deadline behavior; schema compatibility and rollback; log redaction and trace context. Examples of frontend decisions: loading/error/empty/cancel state, stale response handling, accessibility behavior and what text is rendered. These are review/diagnosis exercises, never code-writing tasks.

## What this route can and cannot establish

Repeatedly using a working product can build useful backend/frontend systems understanding **when paired with active tracing, prediction, diagnosis and design review**. Merely using the application or reading generated code is not enough to claim backend expertise. Short role-bank drills provide limited hands-on interview practice, but do not demonstrate independent capstone application delivery or guarantee readiness for any coding round. The separate DSA route remains distinct. Check each target role's current requirements and interview format before applying.

Likewise, synthetic ML training exercises establish mechanics only. They do not create production-ML tenure, online experiment results, customer impact, employer experience or hiring readiness. The [production-ML amendment](2026-10-29-production-ml-depth-amendment.md) keeps learner-owned model training while assistant-owned application serving remains explicit.
