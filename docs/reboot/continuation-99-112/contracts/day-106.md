# Day 106 — 2027-02-06: Orchestrate one bounded sequential batch

## Scope

Run one capture and drain no more than one validated batch per invocation; never loop through the remaining backlog. Deliver each selected item. Receipt and ack are separate commits; stop on first error, report committed progress, no auto retry or skip.

- Learner seam: `OneBatchDispatcher.runOnce(int)`; reject ambient transactions before any store call.
- Engineering total: 120 minutes, with 85 implementation/testing, 25 study, and 10 evidence. The study cap includes pauses and teach-back. Unfinished work carries forward and implementation scope shrinks.

### Two completed transactions, not one enclosing transaction

Capture once; read one bounded page only. For each item commit receipt before ack; prove receipt visible from an independent raw connection at ack. Reject ambient transaction before any store call; stop visibly on first failure.

Focused source: [Spring programmatic transactions](https://docs.spring.io/spring-framework/reference/data-access/transaction/programmatic.html).

### Worked row-state trace

Capture batch K1/K2 once → receipt K1 commits → ack K1 commits → receipt K2 fails → stop. K1 remains delivered; K2 remains pending. No next-page loop runs and committed progress is reported.

## Acceptance

- Call order
- separate commits
- bounded sequence
- failure stops
- no retry
- ambient rejected
- when a later item fails, report only earlier committed receipt/ack progress and leave the failed item pending
