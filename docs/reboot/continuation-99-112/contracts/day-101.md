### Recover by reconciliation, not by a high-watermark

Use INSERT…SELECT with an anti-join, deterministic batch ordering, limit 1–20, and ON CONFLICT DO NOTHING. Limit bounds inserted rows, not scan cost/runtime. Re-scan to discover later-committing earlier keys.

Focused source: [PostgreSQL 18 INSERT](https://www.postgresql.org/docs/18/sql-insert.html).

### Worked row-state trace (limit 2)

| Boundary | Source events | Work rows |
|---|---|---|
| Before capture | A, B, C committed | none |
| After capture(2) | A, B, C committed | A, B; C remains absent |

| Third capture(2) | unchanged | A/B/C remain; zero new rows |

The inserted-row limit bounds the batch, not database scan cost or runtime.
