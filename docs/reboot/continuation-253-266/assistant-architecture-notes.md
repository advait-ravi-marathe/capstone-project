# Assistant-supplied architecture notes

The assistant selects one local synthetic identity/document contract behind a trusted adapter boundary and explains it. No actual federation, SAML parser, cloud service or live customer integration. The learner implements/tests; system design is practiced only in the separate interview bank.

<a id="day-253"></a>
## Day 253 — Define the synthetic identity contract

**Architecture:** Assistant-supplied design: a local adapter returns an already-verified typed assertion fixture; its verification flag must be the literal boolean True, never a truthy string or number. A deterministic policy boundary checks issuer, audience, validity, assertion/request/document tenant, group, scope, exact document ID/revision and active status before any bytes are disclosed. Denials use fixed reason codes and never echo claims or document text. The adapter flag is a test fixture, not cryptographic verification; no actual SAML parser, identity provider, AWS account, external write or model action exists. This is the single selected synthetic enterprise-contract branch. The learner implements and tests these supplied decisions; no capstone design proposal or post-hoc justification is assigned.
