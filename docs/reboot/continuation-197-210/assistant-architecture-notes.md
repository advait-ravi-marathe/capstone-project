# Assistant-supplied architecture decisions: Days 197–210

This is a recovery-and-foundations starter, not activation of a live RAG or agent service. The Day 153/154 A/B evidence gate remains unverified/not met. The Days 183–196 StreamForge work remains conditional; this independent toy exercise cannot satisfy its gate.

## Day 197 — Fixture boundary
Use one immutable tuple of synthetic, versioned clauses with owner identifiers. Keeping the corpus fixed makes examples reproducible and avoids introducing customer data, ingestion infrastructure, or a hidden service.

## Day 198 — Owner filter
Filter clauses by the caller's owner identifier before any matching. This models the order of operations required for authorization; it is still only an in-memory exercise and is not a security boundary.

## Day 199 — Deterministic baseline
Use literal token overlap as a transparent baseline. It is intentionally not semantic search, embeddings, an LLM, or a claim of retrieval quality. A future approved scope can compare alternatives against fixed expected source IDs.

## Day 200 — Citation and abstention
Return the exact matched text plus its stable clause/version citation only for one unique match; abstain for zero or ambiguous matches. This makes unsupported behavior observable and testable.

## Day 201 — Adversarial boundary cases
Test foreign-owner wording, ambiguity, empty input, and absent evidence. These cases expose failure modes without asserting that this small fixture covers a production threat model.

## Day 202 — Version identity
Treat `clause_id@version` as the citation identity; do not silently replace source versions. Version-specific approval workflows are deferred until real authorization and an appropriate write seam exist.

## Day 203 — Evaluation examples
Keep a tiny hand-authored set with expected answer status and citation. Expected values are independent literals, not generated by the implementation.

## Day 204 — Metrics vocabulary
Report counts of cited, abstained, incorrect-citation, and foreign-owner exposures for the fixed examples. A small synthetic denominator is a debugging aid, not evidence of quality, fairness, or user benefit.

## Day 205 — Error handling
Reject blank owner/query input and fail closed for unsupported or ambiguous evidence. Do not add retries, provider calls, credentials, or network access.

## Day 206 — Reproducibility
Run the same fixed cases in a fresh Python process and compare canonical JSON output. This checks deterministic serialization only.

## Day 207 — Study and version checks
Review the official AWS SAA and Developer Associate exam guides available at execution time. Recheck versions and registration status; use DVA-C03 guidance only once AWS publishes it. No exam or certification readiness is implied.

## Day 208 — Application checkpoint
Describe which artifacts demonstrate SDE II knowledge and what they cannot establish about senior ownership. This is evidence inventory only; no post-hoc architecture essay or promotion claim.

## Day 209 — Gate inspection
Re-run the authoritative prerequisite checker. If evidence is still absent or non-qualifying, preserve the blocked status and list the exact recovery evidence required. Do not edit historic evidence records.

## Day 210 — Recovery
