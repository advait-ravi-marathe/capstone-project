# CAP-170 — Validate payment replay-attempt identities

**Day:** 042 · 24 Nov 2026 · **Phase:** 1 · **Role:** primary · **Timebox:** 150 minutes

Validate a bounded, read-only retry ledger for synthetic payment reconciliation. This identity is for an attempt record; replay epochs never authorize a new charge and never replace durable payment-effect uniqueness.

## Learner work

Implement `ValidatePaymentIdentities.validateAttemptLedger` in the saved path [`ValidatePaymentIdentities.java`](../../../src/main/java/capstone/coverstory/payments/ValidatePaymentIdentities.java). Require unique `(ownerId, event, replayEpoch, attemptNo)`, nonblank owner/event, nonnegative epoch, positive attempt number, first attempt `1` within each stream, and strictly increasing attempt numbers in input order. A new epoch starts its sequence at one. Keep `terminal` as fixture metadata; this contract does not infer payment outcomes from it.

The seam only returns a report over supplied rows. It must not issue payments, trigger replays, query provider systems, or claim durable payment-effect idempotency. The exact saved cases are in the [`CAP-170 synthetic fixture`](../../../fixtures/coverstory/CAP-170/synthetic-v1.json).
