## Contract

Implement `summarizeLatency(List<MeasuredRequest>) -> LatencyReport` only. Durations use the provided monotonic timer readings in milliseconds. For a nonempty sorted successful-duration sample, nearest-rank `p_q` is `sorted[ceil(q*n)-1]`, with one-based rank. Failed requests remain in total and error counts and contribute only to error maximum. An end-before-start observation emits `INVALID_DURATION` and is excluded from success/error statistics. With no successful observations, percentile and maximum fields are null. Label the result `LOCAL_SYNTHETIC`; both capacity and availability claims remain false.

| Case | Expected behavior |
|---|---|
| 10 successful samples, 10–100 ms | count 10, p50 50 ms, p95 100 ms, success max 100 ms |
| Add failed samples of 200 and 500 ms | success statistics unchanged, 2 errors, error max 500 ms, total 12 |
| End before start | one `INVALID_DURATION` diagnostic; invalid sample excluded |
| No successful samples | null p50, p95, and success max |
| Run label and claims | local synthetic only; no capacity or availability claim |

The instructor oracle is separately coded and checks each expected fixture outcome plus deliberately defective floor-rank, error-mixing, and empty-as-zero variants. Its results verify harness setup only; they do not implement the learner method or demonstrate performance.
