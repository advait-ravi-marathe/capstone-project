The reference witness accepts only bounded mock mode, produces a non-secret effective manifest, and rejects unknown configuration keys such as `skipReconciliation` or `autoSubmit`. It evaluates owner verification, required fields/disclosures, confirmed extraction, exact current review and reconciled balance/refund facts. A ready draft still has no side effect. The witness never creates a submission-pending state or dispatch.

## Instructor boundaries and readiness

The usable exercise is config validation plus a pure readiness truth table. There is no test-only Spring route, production readiness port, React submit-button binding, authenticated end-to-end flow, real dispatch adapter, retained key provider, or insurer call. These are **missing runtime prerequisites**, separate from the timebox: no learner rehearsal/time measurement has been recorded either. Therefore this is scaffold-supported but not assignable/ready-to-start. See the readiness distinction in `HARNESS-COVERAGE.md`.

Run `mvn -Dtest=CAP110InstructorInfrastructureTest test` for instructor-only checks and `mvn -Plearner-tests -Dtest=CAP110AcceptanceTest test` separately for the expected learner TODO outcome. A green instructor oracle is not a learner pass.
