## Supplied contract

- Input has `schemaMajor: 1` and version records with UUID, category, scenario, source ID/version, evidence status, and publication status. Optional `traceTag` is ignored.
- Unsupported major versions and malformed/missing required values produce typed errors; never coerce or return a partially decoded comparison.
- An instructor-owned synthetic slice connects embedded PostgreSQL version history through a Catalog-owned JDBC adapter and Spring `GET /api/catalog/versions` to a React Query comparison component. Its default browser integration uses a narrow decoder adapter under `web/src/test/`; a selectable learner mode exercises the same real HTTP/browser flow with the actual `decodeCatalogEnvelope` TODO. The runtime verifies persistence across Spring restart, retired-version history, bounded same-category selection, rejected categories, and a full outage/recovery cycle: stop Spring, disable stale comparisons and reload without cached rows, restart Spring on the same port, and refetch all three persisted versions. When storage or the service is unavailable, the comparison offers a sanitized export of selected version IDs only. PostgreSQL remains available during the service restart. This is instructor infrastructure, not customer data, real identity, production persistence, or a completed learner decoder.
