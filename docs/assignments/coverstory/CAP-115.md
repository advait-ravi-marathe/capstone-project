## Prepared instructor contract

- Main learner seam: `src/main/java/capstone/coverstory/application/internal/ReviewedOfferAnswerValidator.java`.
- Instructor-only React panel: `web/src/coverstory/application/ReviewedOfferAnswerValidatorPanel.tsx`. The repository uses `web/` as its React root; no duplicate `frontend/` application is created.
- `CAP115ReviewOfferRuntimeIntegrationTest` runs React/Chromium → Vite → test-profile Spring → disposable PostgreSQL.
- Application offer facts, Support citation permissions, and Payments state are obtained through `OfferRevisionFactsPort`, `AuthorizedOfferEvidencePort`, and `OfferPaymentFactsPort`. Test adapters read only their own synthetic fixture concerns; no cross-module repository is used.
- Test-only `CAP115ReferenceAnswerValidator` is independent of the learner seam. It consumes fixed model-shaped response variants and never calls a model.
- The canonical fixture contains immutable quote hashes, integer INR paise, terms, expiry, and owner-scoped source versions.

## Acceptance plan

1. The supported answer must match the exact revised offer ID/hash, 10,000 paise delta, changed term codes and expiry, and cite only owner-authorized `offer-source-a@v2`.
2. A foreign citation, unknown property, missing status, stale hash, or invented claim is rejected before explanation rendering. Authoritative quote differences remain visible.
3. Without an authorized source, `INSUFFICIENT_EVIDENCE` with no citations is valid. Explanation validation does not create a human quote choice.
4. Explicit human choice requires the current revised offer ID, revision, and content hash. The test-only choice receipt is separate; payment remains `NOT_STARTED` and dispatch false.
5. Reload/restart retains the explicit synthetic choice receipt, without creating payment data.
