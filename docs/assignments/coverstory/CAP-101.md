# CAP-101 — Bound authorized assistance context

**Learner outcome:** choose whole, authorized evidence chunks within a fixed input-token cap, preserve exact citations, and abstain when no usable evidence remains. This seam performs no model or provider call.

The saved contract is a proposed 95-minute capstone slice (10 minutes focused docs, 55 minutes bounded build, 30 minutes tests/evidence). These are scheduled limits, not measured learner completion.

## Instructor-prepared seam

- Java 21 learner seam: [`BoundAssistanceContext.java`](../../../src/main/java/capstone/coverstory/application/BoundAssistanceContext.java), `buildContext(Principal, RankedChunks, InputBudget, OutputBudget) -> ContextPlan`.
- Synthetic fixed-token fixture: [`synthetic-v1.json`](../../../fixtures/coverstory/CAP-101/synthetic-v1.json).
- Learner acceptance contracts: [`CAP101AcceptanceTest.java`](../../../src/test/java/capstone/coverstory/application/CAP101AcceptanceTest.java).
- Independent oracle and defect witnesses: [`CAP101InstructorInfrastructureTest.java`](../../../src/test/java/capstone/coverstory/application/CAP101InstructorInfrastructureTest.java).

The seam is intentionally unimplemented. Its TODO is the learner's job: authorize before reading/counting private content, validate the base budget, traverse ranked chunks in order, include each whole chunk only if it fits, retain its exact citation, list only authorized-but-unselected omissions, and return `ABSTAIN` with the manual path if no evidence can be used. An over-cap base returns `INPUT_TOO_LARGE` before touching chunk payloads. Output reservation remains separate from input capacity. Foreign source IDs must not escape in plan metadata.

## Saved synthetic cases

- **CAP-101-CS-01:** base 300; `ai1` 500 and `ar1` 400 fit; `a3` 700 is omitted whole. Result is 1200 input tokens with citations `[ai1]`, `[ar1]`.
- **CAP-101-CS-02:** base 1501 with cap 1500 yields `INPUT_TOO_LARGE`; token-counter/payload calls remain zero.
- **CAP-101-CS-03:** private `br1` owned by B is ranked before A's content, but is excluded before counting or emitting bytes. It cannot affect A's budget.
- **CAP-101-CS-04:** base 300 plus 500, 400, and 300 reaches exactly 1500 and is accepted; a further one-token source is omitted as a whole. No partial source can be cited.
- **CAP-101-CS-05:** when every source is unauthorized or cannot fit whole, return `ABSTAIN` and direct the flow to manual entry. Do not invent a response.

`RankedChunk` exposes content through a lazy accessor so the learner can enforce the authorization boundary before reading. The fixed-token test adapter is synthetic and does not represent a live tokenizer. It is a deterministic budget fixture, not a model integration.

## Run locally

```sh
mvn -q -Dtest=CAP101InstructorInfrastructureTest test
mvn -q -Dtest=CAP101AcceptanceTest test
```

The instructor oracle tests can pass while the learner acceptance suite stops at the explicit `UnsupportedOperationException` TODO. Report those outcomes separately. Neither result establishes independent learner mastery; passing the oracle only shows the starter fixture and contract are internally coherent.

## Architecture and interview reflection

Draw the boundary as `trusted principal → authorization filter → fixed token counter → whole-chunk budget selection → citation-bearing context`. Explain why checking ownership after tokenization or model submission already leaks content, why splitting a chunk can change what its citation supports, and why output reservation is not part of the input budget. The tests exercise a synthetic local selection only; they do not establish provider safety, prompt-injection resistance, or production token counts.
